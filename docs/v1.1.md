## 1. 项目概述

TinyDDT（仿弹弹堂）是一款基于 C/S 架构的实时多人回合制弹道射击游戏。玩家在同一张地形图上轮流发射炮弹，考虑风向和角度，击中对手削减 HP，先将对方 HP 降为零者获胜。

v1.1 项目分为两大模块：

- **服务端（sylar C++ 协程框架 + 微服务）**：采用微服务架构拆分为 gate / login / lobby / battle / data 五个独立服务，通过 etcd 做服务注册与发现、Protobuf 定义 RPC 接口，共享一套权威物理引擎与二维体素地形。
- **客户端（Unity / C#）**：实现战斗 / 网络 / UI / 游戏逻辑模块，通过 TCP 长连接接入网关，对弹道做本地视觉复放。

整体附带一套基于 Protobuf + etcd 的 RPC 框架（位于 `sylar/rpc/`），以及一套客户端诊断日志体系（`src/client/Game/DebugLog.cs`）。

## 3. 可观测性：traceId 端到端透传

### 3.1 设计

gate 在每个入站帧 mint 一个可读 traceId，经 RpcHeader 字段透传到下游服务，关键 RPC 入口日志可关联调用链。

**traceId 格式**：`g<gateId>-a<accountId>-m<msgId>-<seq>`

### 3.2 实现

| 层 | 文件 | 改动 |
|----|------|------|
| proto | `sylar/rpc/rpcheader.proto` | 加 `string trace_id = 4` |
| controller | `sylar/rpc/rpc_controller.{h,cc}` | 加 `m_traceId` 字段 + `SetTraceId/TraceId` |
| 发送侧 | `sylar/rpc/rpc_channel.cc:59-64` | dynamic_cast 到 RpcController，若 TraceId 非空则 set_trace_id |
| 接收侧 | `sylar/rpc/rpc_provider.cc:108-170` | 解析 RpcHeader.trace_id，构造 RpcController 注入 traceId，入口日志带 `[traceId] rpc in:` |
| 业务层 | `src/server/gate/gate_server.{h,cc}` | newCtrl() helper（22 个 handler 统一入口）+ m_rpcSeq 原子序号 |

### 3.3 验证

gate 调 login.ValidateToken，gate 和 login 日志均出现 `[g1-a0-m1-0]` 同一 traceId：

```
gate.log:  [g1-a0-m1-0] gate: login ok account=90005
login.log: [g1-a0-m1-0] rpc in: service=LoginService method=ValidateToken
```

### 3.4 诚实标注

当前 traceId 覆盖率有限：仅 gate 入口和 rpc_provider 入口打 traceId，业务 impl 内部未打。这是"半成品追踪"——traceId 生成和透传完整，但未结合日志系统（LogEvent 无 traceId 字段、LogFormatter 无格式符）。完整结合需要 fiber-local MDC + LogFormatter 格式符。

## 4. 生产化能力

### 4.1 DB 密码环境变量化

`src/server/service_base.cc` 的 `ServiceConfig::load()` 末尾加环境变量覆盖块：

```cpp
if(const char* p = getenv("DDT_DB_HOST"))     db_host = p;
if(const char* p = getenv("DDT_DB_PASS"))     db_pass = p;   // 关键: 密码不再硬编码
// ... 共 9 个环境变量
```

优先级：env > yml > 默认值。启动期主线程串行读取 libc getenv，线程安全。

### 4.2 Redis 连接池

新文件 `src/server/data/redis_pool.{h,cc}`：

- **RedisPool**：mutex + condition_variable，connect 在锁外（sylar hook 下可能 yield），自愈（markUnhealthy）
- **RedisGuard**：RAII 借还 guard（对称 sylar::Database）
- **Subscriber**：独立 redisContext 订阅（不入连接池），支持 subscribe/loop/stop
- **redisPublish**：工具函数（两种重载：用 pool / 独立连接）

`data_service.{h,cc}` 删 `void* m_redis + std::mutex`，改用 `shared_ptr<RedisPool>`。token 操作并行化。

### 4.3 多人战绩端到端落库

#### schema 拆主子表

```sql
CREATE TABLE game_records (
  id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  winning_team TINYINT,   -- 与 proto TeamSide 数值一致(0=RED 1=BLUE)
  duration INT,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE game_record_players (
  id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  record_id BIGINT UNSIGNED NOT NULL,   -- FK → game_records(id) ON DELETE CASCADE
  account_id BIGINT UNSIGNED NOT NULL,  -- FK → accounts(id)
  team TINYINT NOT NULL,
  is_winner TINYINT(1) DEFAULT 0,
  damage_dealt INT DEFAULT 0,
  ...
);
```

#### proto 扩展

`rpc.proto` GameRecordReq 加 `message PlayerStat { account_id/team/is_winner/damage_dealt }` + `repeated PlayerStat players = 4` + `TeamSide winning_team = 5`（旧字段 1/2/3 保留兼容）。

#### data 层事务 + 批量插入

`data_service.cc::SaveGameRecord` 重写：Database + Transaction，BEGIN → INSERT 主表 → getLastInsertId → 批量 INSERT 子表 → COMMIT，失败 rollback。兼容旧字段路径。

#### battle 累计 damageDealt + 异步落库

- `battle_room.h` BattlePlayer 加 `int damageDealt = 0`
- `battle_room.cc` onShoot AOE 循环内 `shooter->damageDealt += finalDmg`
- `battle_room.cc::checkGameOver` 游戏结束时调 `saveGameRecordLocked`：锁内快照 players + 算 duration，锁外 schedule 到独立协程调 data.SaveGameRecord（避免深 RPC 栈压在 onShoot 协程上）

### 4.4 gate 注册式分发

`gate_server.{h,cc}`：

```cpp
typedef std::function<void(ClientSession::ptr, const std::string&)> Handler;
std::unordered_map<uint16_t, Handler> m_handlers;
std::unordered_set<uint16_t> m_preAuthMsgs;
```

构造调 `registerHandlers()`，21-case switch 改为：预登录白名单（5 个 LOGIN/REGISTER/HEARTBEAT/LOGOUT/SET_GENDER）查 static const map，已登录（16 个）查 m_handlers。新增 msg_id 只加一行注册。

## 5. Redis 进阶：在线状态 + 世界聊天 Pub/Sub

### 5.1 在线状态（Redis Set）

**链路**：

```
gate onLogin → schedule → data.SetOnline → Redis SADD online:players
gate delSession → schedule → data.SetOffline → Redis SREM online:players
lobby.FriendList RPC → data.GetFriendList → Redis SMEMBERS → 回填 online 字段
```

**关键代码**：
- `data_service.cc:625-667`：SetOnline/SetOffline（SADD/SREM online:players）
- `data_service.cc:523-551`：GetFriendList 内部 SMEMBERS 批量查在线 id
- `rpc.proto:70-71`：DataService 加 SetOnline(IdReq) / SetOffline(IdReq)
- `gate_server.cc::onLogin`：schedule 异步调 SetOnline（不阻塞 LOGIN_RESP）
- `gate_server.cc::delSession`：异步闭包调 SetOffline

**修复缺陷**：v1.0 的 GetFriendList 的 online 恒 false（architecture-analysis.md §8.3 建议 7），本次修复。

### 5.2 世界聊天 Pub/Sub

**链路**（替代原 lobby → gate.NotifyAllOnline RPC）：

```
玩家 → gate → lobby.Chat(WORLD) → data.PublishWorldChat
                                    ├─ MySQL 持久化(chat_history)
                                    └─ Redis PUBLISH chat:world <ChatNotify payload>
gate 订阅线程(std::thread) ← SUBSCRIBE chat:world ← Redis
gate 收到 → iom->schedule → 遍历 m_accountToSession → sendToSession(MSG_CHAT_NOTIFY)
```

**关键代码**：
- `redis_pool.h:71-96`：Subscriber 类（subscribe/loop/stop + MsgCallback）
- `data_service.cc:679-714`：PublishWorldChat（持久化 + PUBLISH）
- `gate_server.cc:914-955`：startWorldChatSubscriber（独立 std::thread 订阅 + iom->schedule 投递）
- `lobby_service.cc:555-573`：Chat 方法世界频道分支改走 PublishWorldChat

### 5.3 关键设计决策

| 决策 | 理由 |
|------|------|
| 订阅用独立 std::thread（非协程） | hiredis redisGetReply 阻塞，sylar hook 不感知 |
| 订阅连接不入 RedisPool | SUBSCRIBE 让连接进入订阅模式，不能复用做普通命令 |
| 订阅线程用 iom->schedule 投递 | 裸线程的 IOManager::GetThis() 返回 nullptr → SIGSEGV（踩坑修复） |
| 订阅连接清除 command_timeout | redisConnectWithTimeout 会设 command_timeout，导致 redisGetReply 1.5s 超时断开（踩坑修复） |
| 仅世界聊天用 Pub/Sub | ROOM/TEAM 不能丢，Pub/Sub 是 fire-and-forget |

### 5.4 诚实标注

Pub/Sub 是 fire-and-forget：gate 重启瞬间会丢消息、无 ACK、Redis 宕机断聊。可选升级方案：Redis Stream（持久化 + ACK + consumer group）。

## 7. 运维与修复

### 7.1 login 服栈溢出修复

**现象**：login 服 core dump，gdb 显示 `stack smashing detected at Fiber::swapOut`。

**根因**：login.ValidateToken 在主 RPC 协程上做 2 次同步 data RPC（LoadToken + GetAccountById），每次新建 EtcdClient（gRPC channel 重对象），1MB 协程栈在高并发登录时溢出。

**修复**：`src/server/conf/login.yml` fiber.stack_size 从 1048576 (1MB) 改为 2097152 (2MB)。

### 7.2 fleet.sh 修复

**问题**：原 `pkill -f "$BIN/ddt_"` 只匹配绝对路径，杀不掉用相对路径（`./ddt_xxx`）启动的幽灵进程，导致端口占用、新进程 bind 失败。

**修复**：

```bash
PATTERN="ddt_(login|gate|lobby|battle|data)[ ]"
kill_all_ddt() {
    pkill -f "$PATTERN" 2>/dev/null || true
    sleep 1
    if pgrep -f "$PATTERN" >/dev/null 2>&1; then
        pkill -9 -f "$PATTERN" 2>/dev/null || true   # 兜底 SIGKILL
        sleep 1
    fi
}
```

### 7.3 客户端 Bug 修复（撤回）

撤回了两项误修复：
- **OnApplicationFocus 误丢消息**：focus 抖动触发 CheckAndRecover 清空 backlog，丢合法消息
- **主线程看门狗**：sylar hook × gRPC 多进程冲突导致误判

## 8. 代码风格统一

### 8.1 范围

60+ 文件，覆盖 `sylar/rpc/` + `src/` + `scripts/` + `tests/`。

### 8.2 原则

1. **删除文件顶部大段注释块**（`// ==== 模块介绍 ==== // 详细说明... // ====`）
2. **保留函数级注释**（每个函数上方 1-3 行简短中文说明）
3. **保留行内"为什么"注释**（解释设计意图的）
4. **重格式化**：4 空格缩进、K&R 花括号、单行 if 拆多行、单语句单行、函数间 1 空行、末尾 1 换行
5. **代码逻辑绝对不动**（变量名/函数体/控制流/类型/include 完全保留）

### 8.3 验证

8 个目标（5 服务 + 3 冒烟测试）全部重新编译通过，零 error。
