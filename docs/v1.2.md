## 1. 项目概述

TinyDDT（仿弹弹堂）是一款基于 C/S 架构的实时多人回合制弹道射击游戏。玩家在同一张地形图上轮流发射炮弹，考虑风向和角度，击中对手削减 HP，先将对方 HP 降为零者获胜。

v1.2 延续 v1.1 的两大模块划分：

- **服务端（sylar C++ 协程框架 + 微服务）**：gate / login / lobby / battle / data 五个独立服务，通过 etcd 做服务注册与发现、Protobuf 定义 RPC 接口。本版重点重写了 RPC 传输层（长连接多路复用）与 data 服务的 DB 执行模型（双通道线程池）。
- **客户端（Unity / C#）**：通过 TCP 长连接接入网关。本版用 BattleActionQueue 取代多个布尔标记 + 协调协程，彻底重写了战斗时序的核心调度。

## 3. 框架层：异步 Socket 流与 RPC 多路复用

### 3.1 AsyncSocketStream + FiberSemaphore

新文件 `sylar/net/async_socket_stream.{h,cc}`：基于 `FiberSemaphore` 的协程级串行发送流。

**设计要点**：

- **多协程 enqueue，单 doWrite 协程串行消费**：任意协程调 `send()` 入队后立即返回，由唯一的 doWrite 协程通过 `m_sem`（FiberSemaphore）唤醒后顺序写 socket，保证字节流不被交错。
- **doRead/doWrite 生命周期管理**：`m_waitSem` 初始为 2（等待 doRead + doWrite 都退出），重连前必须 `waitFiber()` 等两者都结束，避免旧协程操作已关闭的 fd。
- **替代手搓 sendQueue**：业务侧（gate 的 GateSendStream）继承它即可获得协程级安全发送，无需自旋锁 + 手动 drain 协程。

### 3.2 RpcStream：请求-响应配对

新文件 `sylar/rpc/rpc_stream.{h,cc}`：继承 AsyncSocketStream，实现 RPC 的请求-响应配对。

**帧格式**：`[4B total_size (BE)][4B request_id (BE)][response protobuf body]`

- **request_id 匹配**：每个调用生成递增 `request_id`，写入 RpcHeader；doRead 协程解析响应的 request_id，唤醒对应阻塞协程（协程级 `wait`）。
- **doRecv 返回 Ctx**：doRead 调 doRecv 阻塞读完整响应帧，解析 request_id，返回对应的等待 Ctx，由调用方唤醒。

### 3.3 RpcChannel 多路复用重写

`sylar/rpc/rpc_channel.cc` 重写为两条路径：

| 路径 | 函数 | 适用场景 |
|------|------|----------|
| 长连接多路复用 | `callMethodMultiplexed` | 有 pool：通过 RpcStream 发送 + request_id 匹配，单连接并发多请求 |
| 短连接兼容 | `callMethodShort` | 无 pool：每次新建连接，发完即关（向后兼容） |

`rpcheader.proto` 加 `uint32 request_id = 5`（请求唯一 ID，多路复用响应匹配）。

调用入口根据是否传入 pool 自动分流到对应路径。

### 3.4 RpcChannelPool 流管理

`sylar/rpc/rpc_channel_pool.{h,cc}` 加流实例池管理：

- `acquireStream(ip, port)`：按 (ip,port) 复用或新建 RpcStream（连接失败/地址非法返回 nullptr）。
- `releaseStream(ip, port, stream)`：用完归还，供下次复用。

### 3.5 RpcProvider 长连接

`sylar/rpc/rpc_provider.{h,cc}` 改为**循环处理（不 break）**：处理完一个请求后继续读下一个，`sendResponse` 不主动 close 连接，从而支持单连接上多请求-多响应的多路复用。

### 3.6 LoadBalance 框架（未集成）

新文件 `sylar/rpc/load_balance.{h,cc}`：含 `HolderStats`（时间窗口统计）/ `HolderStatsSet`（按秒分片）/ `LoadBalanceItem` / RoundRobin / Weight 等负载均衡基础设施。

**诚实标注**：本框架已实现但**未集成到 RpcChannelPool**。当前 pool 仍按 (ip,port) 固定连接，未基于统计做后端选择。属于为后续多副本负载均衡预留的地基。

### 3.7 etcd_client PImpl 去除 + 全局 C++17

- `sylar/rpc/etcd_client.{h,cc}` 重写：去掉 3 个 Impl 结构体（约 230 行 PImpl 包装），直接 include etcd 头文件。
- `CMakeLists.txt`：`-std=c++11` → `-std=c++17`，全项目统一 C++17（etcd 现代头文件依赖）。

## 4. 服务端业务层：DB 双通道与 RPC 池化

### 4.1 DbWorkerPool 双通道

新文件 `src/server/data/db_worker.{h,cc}`：异步/同步双通道 DB 线程池。

| 通道 | 方法 | 语义 |
|------|------|------|
| Async | `execute(dbTask)` | 写操作 fire-and-forget，DB 线程执行完静默结束（不回调 IOManager） |
| Synch | `query(dbTask, onComplete)` | 读操作 submit，DB 线程执行完后把 onComplete 投回 IOManager 协程 |

`data_main.cc` 注入 DbWorkerPool；`data_service` 的 19 个 RPC 方法按读/写性质改走对应通道。

### 4.2 PreparedStmt 全面应用

- `sylar/orm/stmt.cc::queryRows()` 补上 `mysql_stmt_bind_param`（详见 §8.2）。
- `data_service.cc` 16 处 `esc()` 裸 SQL 改为 PreparedStmt，杜绝 SQL 注入与类型转换隐患。

### 4.3 Redis 操作移出 DB 线程

SaveToken / LoadToken / DeleteToken / SetOnline / SetOffline / GetFriendList 的 Redis 操作从 DbWorkerPool 的 dbTask 移回 RPC 协程同步执行。

**原因**：DB 线程下 sylar hook 使 hiredis 非阻塞 fd 的 `read` 返回 EAGAIN，在 DB 线程内无法正确 yield，导致 Redis 命令异常。这些操作放回 RPC 协程后，sylar hook 正常工作。

### 4.4 聊天持久化重设计

| 频道 | v1.1 | v1.2 |
|------|------|------|
| WORLD | MySQL `chat_history` | **Redis List（LPUSH/LTRIM/LRANGE）**，只保留最近 200 条，不落盘 |
| ROOM / TEAM | 同上 | **不落盘（ephemeral）**，返回空历史 |
| PRIVATE | 同上 | **MySQL `chat_history`**（保留持久化） |

`data_service.cc::PublishWorldChat` 改为 `LPUSH chat:world` + `LTRIM 0 199` + `PUBLISH`；`LoadChatHistory` 世界频道走 Redis LRANGE，ROOM/TEAM 返回空。

### 4.5 4 个服务全改 RpcChannelPool

login / lobby / battle / data 四个服务（gate 调用它们的 RPC）全部改用 RpcChannelPool 长连接多路复用，替代 v1.1 的短连接逐次新建。

## 5. 服务端业务层：gate 与 battle 改造

### 5.1 gate GateSendStream

`src/server/gate/gate_server.{h,cc}`：新增 `GateSendStream(RpcStream)` 继承 AsyncSocketStream，替代手搓 sendQueue + drainAndSend。发送路径统一走 `AsyncSocketStream::send` 异步入队。

由于 GateSendStream 只发不收，`doRecv` 恒返回 nullptr，因此构造时**不启动 doRead 协程**（否则会触发 §8.1 的 busy-loop）。

### 5.2 gate KICK 同步发送

`kickExistingSession` 改为同步发送 KICK_NOTIFY + 延迟 200ms close。

**修复的缺陷**：v1.1 把 KICK 异步入 stream 队列后立即 close 连接，导致 doWrite 还没消费到 KICK 帧 socket 已关闭 → KICK 没发出去 → 客户端只看到断线 → 触发自动重连死循环。改为 `sock->send` 同步发 + 延迟关闭后，客户端能正确收到 KICK_NOTIFY 并停止重连。

### 5.3 battle urgent broadcast

`src/server/battle/battle_room.cc::broadcast`：对 ShootResult / TurnStart / GameOver 同步推送（不走 schedule），仅 MoveNotify 走 schedule。

**原因**：移动期间高频 MoveNotify 的 schedule 协程积压在 IOManager 队列，若 ShootResult 也 schedule，会排在 MoveNotify 后面 → 射击动画延迟启动。同步推送 urgent 消息保证射击反馈即时。

### 5.4 battle 友军伤害 / 同归于尽

- **友军伤害**：自己 / 同队受 AOE 伤害但 HP 最低保 1（不致死）；坠落照死（不分敌友）。
- **同归于尽**：全员阵亡时判当前出手方胜利（避免平局悬空）。

## 6. 客户端：战斗时序重写

### 6.1 BattleActionQueue

新文件 `src/client/Battle/BattleActionQueue.cs`：串行动作队列，战斗表现的时序核心。

**Action 类型**：

| Action | 职责 |
|--------|------|
| `BattleAction`（抽象基类） | 定义 onEnter / onUpdate / onLand 等钩子 |
| `ShootAction` | 执行弹道 + 爆炸 + 落点，8s 总超时强制结算 |
| `TurnStartAction` | 切换当前出手方，提示用独立协程不阻塞队列 |
| `GameOverAction` | 结束流程，执行后清空队列不再处理后续 |
| `WaitAction` | 固定时长等待（占位） |

`BattleActionQueue` 是 MonoBehaviour 调度器，串行执行入队 Action。

**替代的旧机制**：v1.1 用 `resolvingShoot_` / `camFrozenAfterShoot_` / `pendingTurnStart_` 三个布尔 + 多个协调协程管理时序，竞态难控。改为单队列后天然有序（ShootAction 必在 TurnStartAction 之前完成）。

### 6.2 OnShootResult / OnTurnStart 改入队

消息 handler 不再直接执行，而是转换为对应 Action 入队串行执行。`MoveNotify` 直接应用不入队（高频，且不与射击冲突）。

### 6.3 pendingTurnStart 单槽 → Queue

防止服务端连发 TurnStart 时后条覆盖前条（v1.1 单布尔槽位会丢消息）。

## 7. 客户端：表现与网络修复

### 7.1 PlayerEntity 位置插值

- **远程玩家**：用 lerp 平滑位置，消除 15px RPC 跳变带来的瞬移。
- **本机玩家**：直接定位（每帧增量精确，不插值）。
- 新增 `ForcePosition` 方法：降落动画阶段强制对齐（绕过 lerp）。

### 7.2 开场序列简化

`BattleField.cs`：原 `PlayLanding` + `PlayIntro`（多阶段 `WaitUntilCamReached`）→ 单一 `PlayIntro`（降落 + 固定时长巡视 + 收尾）。

全程只用固定时长的 `WaitForSeconds`，**不依赖 `WaitUntilCamReachedOrTimeout`**。

**修复的缺陷**：`WaitUntilCamReached` 被 TurnStartAction 覆盖 `camTarget_` 导致条件永不满足 → 协程永久挂起 → 开场卡死。

### 7.3 爆炸动画重写

去掉 `SpriteDrawMode.Sliced`（无 border 的 SpriteCreate 在该模式下不渲染），改用 Simple 模式 + `localScale` 缩放 + 贴图 4 帧逐帧播放。

### 7.4 高角度落点修正

`PlayTrajectory` 最后一个轨迹点强制对齐服务端下发的 `hit_x / hit_y`，消除 int 截断导致的角度微小差异（否则爆炸位置与命中判定不一致）。

### 7.5 shotLocked_ 超时兜底

`BattleController.cs`：出手 / Pass 后若 15s 未收到 TurnStart 则强制解锁 `shotLocked_`（防消息丢失/断线导致永久锁操作无法出手）。

### 7.6 EndTransition 锁外重放

原持锁 Dispatch 改为**锁内快照 + 锁外 Dispatch**，避免在锁内做可能阻塞的分发。

### 7.7 mainThreadQueue 满告警

主线程队列满时丢弃关键消息打 Warning（便于排查丢消息）。

### 7.8 KICK_NOTIFY 战斗场景订阅

`BattleController` 加 `OnKick` 处理。v1.1 只在 LobbyUI 订阅 → 战斗中被踢不处理（玩家卡在战斗界面）。

### 7.9 重连状态清除

`MarkLoggedIn` 清除 `ConnState`。v1.1 重连成功后状态永远停在 Reconnected，导致后续状态判断异常。

### 7.10 FollowProjectile 退出恢复相机模式

`FollowProjectile` 结束后 `camMode_` 切回 `PanFollow`。v1.1 停在 FollowProj → 相机卡在天空不回落。

### 7.11 ShootAction 总超时

用 `Time.realtimeSinceStartup`（不受暂停影响），8s 强制结算，防 App Nap（macOS 后台限速）导致卡死。

## 8. 关键缺陷修复

### 8.1 doRead busy-loop（卡死全家）

`sylar/net/async_socket_stream.cc::doRead`：当 `doRecv` 返回 nullptr 时 **break 退出循环**。

**根因**：原实现不 break，在非抢占式协程调度下，doRead 协程空转独占线程 → 4 个工作线程被打满 → 所有其他协程饿死 → 客户端全部卡死。

**取舍**：nullptr 可能是真断连（应退出）也可能是偶发无匹配 Ctx。统一 break 后由 start 重启 doRead（代价是一次重连），远好于 100% CPU 空转。

### 8.2 PreparedStmt queryRows 漏 bind_param

`sylar/orm/stmt.cc::queryRows()` 补上 `mysql_stmt_bind_param`。

**根因**：`bind_result` 绑的是输出列，与输入参数绑定（bind_param）是两套独立缓冲，必须分开提交。早期实现遗漏此步 → `WHERE name=?` 占位符恒为 NULL → 查询永远返回 0 行（看似查询正常但拿不到数据）。

### 8.3 Socket::reconnect 新增

`sylar/net/socket.{h,cc}` 新增 `reconnect(timeout_ms)`，供 AsyncSocketStream 重连路径调用。

## 10. 运维

### 10.1 fleet.sh SIGKILL 优先

`scripts/fleet.sh` 的 `kill_all_ddt` 改为 **SIGKILL 优先**。

**原因**：busy-loop 进程（如 §8.1 修复前的卡死进程）独占线程，信号处理协程不被调度，无法响应 SIGTERM。先 SIGKILL 直接强杀，再确认无残留。

| C6 | 爆炸动画 | SpriteDrawMode.Sliced | **Simple + localScale + 4 帧逐帧** |
| C7 | 落点修正 | 无 | **末点对齐 hit_x/hit_y** |

### 11.5 关键缺陷修复

| # | 项 | 现象 | 修复 |
|---|----|------|------|
| F1 | doRead busy-loop | 4 线程打满，客户端全卡死 | **doRecv 返回 nullptr 时 break** |
| F2 | queryRows 漏 bind_param | WHERE=? 恒 NULL，查询 0 行 | **补 mysql_stmt_bind_param** |
| F3 | KICK 异步后 close | 客户端只看到断线，重连死循环 | **同步 send + 延迟 close** |
| F4 | shotLocked_ 无超时 | 消息丢失则永久锁操作 | **15s 强制解锁** |
| F5 | 开场 WaitUntilCamReached | camTarget_ 被覆盖，开场卡死 | **改固定时长 WaitForSeconds** |
| F6 | 战斗中 KICK 不处理 | 战斗被踢卡界面 | **BattleController 加 OnKick** |
| F7 | 重连状态不清 | 永远停在 Reconnected | **MarkLoggedIn 清 ConnState** |
| F8 | FollowProj 相机不回落 | 相机卡天空 | **退出切回 PanFollow** |
| F9 | ShootAction 无总超时 | App Nap 卡死 | **realtimeSinceStartup 8s 强制结算** |
| F10 | fleet.sh SIGTERM 无效 | busy-loop 进程杀不掉 | **SIGKILL 优先** |
