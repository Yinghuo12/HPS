# TinyDDT — 项目文档 v1.0

> 版本状态：架构级重构完成。客户端由 OpenGL(C++/ImGui) 重构为 **Unity(C#)**；服务端由单进程 WebSocket 三层结构（gate/lobby/match）演进为 **五服务微服务架构**（gate / login / lobby / battle / data）；服务发现由 ZooKeeper 迁移至 **etcd**；通信由 WebSocket 迁移至 **TCP 长连接 + Protobuf**。

> 相对 v0.4 的主要变化：**微服务化 + 客户端重写**——服务端拆分为 5 个独立可执行文件，各自在 etcd 注册、经 Protobuf RPC 互联；客户端整体改用 Unity 引擎与 C# 重写。详见第 11 节。

## 1. 项目概述

TinyDDT（仿弹弹堂）是一款基于 C/S 架构的实时多人回合制弹道射击游戏。玩家在同一张地形图上轮流发射炮弹，考虑风向和角度，击中对手以减少其 HP，率先将对方 HP 降为零者获胜。

v1.0 项目分为两大模块：

- **服务端（sylar C++ 协程框架 + 微服务）**：采用微服务架构拆分为 gate / login / lobby / battle / data 五个独立服务，通过 etcd 做服务注册与发现、Protobuf 定义 RPC 接口，共享一套权威物理引擎与二维体素地形。
- **客户端（Unity / C#）**：实现战斗 / 网络 / UI / 游戏逻辑模块，通过 TCP 长连接接入网关，对弹道做本地视觉复放。

整体附带一套基于 Protobuf + etcd 的 RPC 框架（位于 `sylar/rpc/`）。

### 核心功能

- **回合制弹道射击**：服务端权威物理引擎，客户端本地复算弹道做视觉回放，逻辑以服务端为准
- **二维体素地形**：地形以 bitset 二维网格表达，爆炸只挖圆内格子（平台保留），彻底解决穿地形 / 误判掉落
- **房间系统**：支持创建 / 加入 / 离开 / 准备 / 切换队伍 / 切换武器，对局结束后自动返回大厅
- **聊天系统**：综合 / 世界 / 房间 / 队伍 / 私聊频道通信
- **账号系统**：HTTP 登录拿 token，登录服校验后长连接接入，基于 MySQL 持久化 + Redis 会话管理
- **Protobuf 通信协议**：网关帧 `[length][msg_id][payload]`，客户端 / 服务端共享物理公式与地形位图
- **自动重连**：断线后指数退避自动重连，重连后用缓存 token 自动登录恢复状态
- **主线程无阻塞**：网络收发在独立线程，发送队列化，杜绝 TCP 反压导致画面冻结

## 2. 技术选型

### 2.1 服务端

| 组件 | 技术 | 用途 |
|------|------|------|
| 框架 | sylar | C++ 协程框架，提供 IOManager、TcpServer、HTTP、日志、配置等基础设施 |
| 并发 | 协程（ucontext）+ epoll | N-M 协程调度 + Hook 透明化阻塞 IO |
| 序列化 | Protobuf | RPC 接口定义、游戏协议序列化 |
| 通信 | TCP 长连接 | 客户端 ↔ 网关实时双向通信 |
| 服务发现 | etcd v3 | 5 个微服务的注册与发现（替代 ZooKeeper） |
| 数据库 | MySQL | 账号、玩家资料、聊天记录、对战记录、好友关系持久化 |
| 缓存 | Redis | 会话 token、在线状态 |
| 配置 | YAML | 服务参数配置（物理、地形、战斗、连接） |
| 构建 | CMake + Make | 编译构建（C++11 为主，etcd 客户端 C++17） |

### 2.2 客户端

| 组件 | 技术 | 用途 |
|------|------|------|
| 引擎 | Unity | 游戏引擎、场景管理、MonoBehaviour 生命周期 |
| 语言 | C# | 全部业务 / 战斗 / 网络 / UI 脚本 |
| 序列化 | Protobuf (Google.Protobuf.dll) | 与服务端共享 `common.proto` / `gate.proto` |
| 网络 | TcpClient / UnityWebRequest | TCP 长连接 + HTTP 登录接口 |
| 渲染 | SpriteRenderer / Texture2D | 精灵渲染、二维体素地形、爆炸破坏 |
| 数学 | 自研解析弹道公式 | 与服务端解析式一致，本地视觉复放 |

> v0.4 客户端为 OpenGL 3.3 + ImGui + GLFW + FreeType + GLM（C++）；v1.0 整体重写为 Unity C#，对应第三方依赖（freetype / glad / glfw / glm / imgui）已从 `thirdparty/` 移除。

## 4. 通信协议

### 4.1 三类协议文件

协议定义在 `src/proto/`，共 3 个 `.proto`（`syntax = "proto3"`, `package ddt`）：

| 文件 | 角色 | 是否含 RPC Service |
|------|------|----|
| `common.proto` | 共享枚举 / 类型，被 gate / rpc import | 否 |
| `gate.proto` | 客户端 ↔ 网关消息目录（60+ 消息） | 否（仅消息） |
| `rpc.proto` | 服务间 RPC 接口（`cc_generic_services = true`） | 是（4 个 Service） |

> **关于多态**：v0.4 使用 `oneof payload` 聚合；v1.0 改为 **`msg_id` 外挂路由**——每个 `msg_id` 唯一映射到一种消息类型，无 wrapper 消息、无 `oneof`。帧层只依赖 `msg_id.h` / `MsgId.cs`，不需要 proto 头。

### 4.2 帧格式（客户端 ↔ gate）

```
┌───────────┬───────────┬────────────────────┐
│ 4B length │ 2B msg_id │ protobuf payload   │   (length, msg_id 均为大端序)
└───────────┴───────────┴────────────────────┘
length = 2 + payload.size()
```

- 编解码：`common/frame.cc::Frame::{encode,decode}`（服务端）与 `client/Network/FrameCodec.cs`（客户端）字节级一致。
- 登录流程：HTTP `POST /login` 拿 token → TCP 建链 → 首帧发 `LOGIN{token}` → 收 `LoginResp` → 后续业务帧。
- 心跳：`HEARTBEAT(91) ↔ HEARTBEAT_RESP(92)`，客户端 10s 一次。

### 4.3 共享类型（common.proto）

**枚举：**
- `Result`：SUCCESS / FAIL / NOT_FOUND / AUTH_FAIL / ALREADY / FULL / BAD_PARAM
- `TeamSide`：TEAM_RED / TEAM_BLUE
- `Gender`：GENDER_NONE / GENDER_MALE / GENDER_FEMALE
- `ChannelType`：WORLD / ROOM / TEAM / PRIVATE / SYSTEM

**消息：** `PlayerState`（战斗快照）、`PlayerSlot`（房间座位）、`RoomInfo`、`PhysicsParamsMsg`（服务端下发物理参数）、`FriendInfo`、`AccountInfo`。

### 4.4 网关消息（gate.proto，节选）

| 类别 | 消息（MsgId） |
|------|------|
| 账号 | `LoginReq/Resp(1/2)`、`RegisterReq/Resp(3/4)`、`SetGenderReq/Resp(27/28)`、`LogoutReq/Resp(24/26)`、`KickNotify(25)` |
| 房间 | `RoomList(10/11)`、`CreateRoom(12/13)`、`JoinRoom(14/15)`、`LeaveRoom(16/17)`、`Ready/ReadyNotify(18/19)`、`SwitchTeam(20/21)`、`RoomUpdate(22)`、`RoomListNotify(23)`、`SwitchWeapon(29/50)` |
| 战斗 | `RoomReadyNotify(30)`、`TurnStartNotify(31)`、`Shoot(32)`、`ShootResultNotify(33)`、`Move/MoveNotify(34/35)`、`Pass(36)`、`GameOverNotify(37)`、`OpponentLeftNotify(38)`、`AimBegin(39)` |
| 社交 | `Chat/ChatNotify(40/41)`、`ChatHistory(42/43)`、`PrivateChat(44)`、`FriendAdd(45/46)`、`FriendList(47/48)` |
| 其它 | `ErrorNotify(90)`、`Heartbeat/Resp(91/92)` |

关键战斗消息字段：

```

  ├── players[]            // 完整玩家列表（位置/HP/角度/方向）
  ├── wind                 // 首回合风力
  ├── physics_params       // PhysicsParamsMsg（air/wind/gravity/force）
  ├── max_move_per_turn    // 移动限额
  ├── map_name             // "rainbow" / "ghost"
  ├── terrain_bitmap       // 二维体素位图（替代 1D 高度图）
  ├── terrain_w / terrain_h
  └── first_turn_id

  ├── turn_account_id / wind / turn_number
  └── players[]            // 双方完整状态

ShootReq(32) → ShootResultNotify(33)
  ├── angle / force / is_fly / weapon_id
  ├── hit_x / hit_y / hit_player / hit_account_id
  ├── damage / DamageType{NORMAL,CRITICAL,BLOCK}
  ├── start_x / start_y / direction
  └── updated_players[]
```

### 4.5 RPC 服务（rpc.proto，cc_generic_services = true）

4 个 Service、共 25 个方法：

| Service | 实现于 | 关键方法 |
|---------|--------|----------|
| `LoginService` | login | `ValidateToken`、`Register`、`Login` |
| `DataService` | data | `CreateAccount`、`GetAccount*`、`VerifyPassword`、`UpdateGender`、`GetProfile`、`UpdateWinLoss`、`SaveToken`、`LoadToken`、`DeleteToken`、`SaveGameRecord`、`AddFriend`、`GetFriendList`、`SaveChat`、`GetChatHistory`、`GetPrivateHistory`（18） |
| `LobbyService` | lobby | `RoomList`、`CreateRoom`、`JoinRoom`、`LeaveRoom`、`Ready`、`SwitchTeam`、`SwitchWeapon`、`FriendAdd`、`FriendList`、`Chat`、`PrivateChat`、`ChatHistory`（12） |
| `BattleService` | battle | `EnterBattle`、`Shoot`、`Move`、`Pass`、`AimBegin`、`LeaveBattle`（6） |
| `PushService` | gate（反向） | `NotifyClient`、`NotifyClients`（批量）、`NotifyAllOnline`（3） |

> `PushService` 是 lobby/battle 反推消息回客户端的唯一通道，`NotifyReq.payload` 直接装 gate-proto 序列化字节 + gate `msg_id`。

## 5. 服务端

### 5.1 公共启动层（`src/server/service_base.h/.cc`，命名空间 `ddt`）

- **`ServiceConfig`**（单例）：一个结构体装载某服务所需的全部配置——身份（`service_name` / `etcd_endpoint` / `etcd_ttl`）、监听（`host` / `port` / `advertise_host` / `advertise_port`）、DB / Redis、心跳，以及一大块物理 / 游戏 / 战斗 / 玩家调参（`air_factor` … `start_hp`）。`load(path)` 读取 YAML（`db/redis/heartbeat/physics/game/combat/player` 段），`advertiseAddr()` 把 `0.0.0.0` 替换为 `127.0.0.1` 作为 etcd 注册地址。
- **`ServiceRunner`**：统一启动器。`init(argc, argv)` 解析 `-c conf.yml`（依次回退 `conf/{name}.yml`、`../conf/...`、`bin/conf/...`），同时加载 DDT 配置与 sylar 全局配置（如 `fiber.stack_size` 必须在 IOManager 创建协程前设置）。`installSignal()` 捕获 SIGINT/SIGTERM：首次触发优雅 `IOManager::stop()`，第二次 `_exit(0)`。

### 5.2 五个微服务

#### Gate 网关（`server/gate/`，端口 8100，推送 RPC 在 8101）

- `gate_main.cc`：`ServiceRunner("gate")`，默认 port=8100；4 线程 IOManager；共享 `TimeWheel`（1s 步进，60min 上限）做心跳调度；构造 `GateServer`（`TcpServer` + `PushService` 实现）；额外起一个 `RpcProvider` 在 8101 注册 `gate` 为 `PushService`。
- `gate_server.h/.cc`（最大源文件）：`GateServer : public sylar::TcpServer, public PushService`。
  - `ClientSession` 持有每个连接状态（sock / accountId / name / token / gender / lastRecvMs / gatewayId / sendQueue / sendMutex / sendBusy）。
  - **每会话发送队列 + 按需 drain 协程**：所有对同一 fd 的发送串行化到单条协程，规避 sylar `SYLAR_ASSERT` 在同 fd 上并发 `addEvent(WRITE)` 导致的 abort。
  - 双向 session 表（`RWMutex`）：`m_accountToSession`、`m_sockToSession`。
  - RPC channel 缓存（lobby/battle/login/data）——**短连接**（连接池曾因 sylar hook 下 fd 复用竞态回滚）。
  - `handleClient`：读 4B 长度 + 字节序转换 + 读 body + `Frame::decode` + `switch(msgId)` 分发；登录前只允许 LOGIN/REGISTER/HEARTBEAT/LOGOUT/SET_GENDER。
  - 登录流程支持 **token 登录**（重连：直连 `ValidateToken`）与 **账密登录**（首次：先 `Login` 拿 token 再 `ValidateToken`）；成功后 **踢人**（`KICK_NOTIFY` 409）。
  - 断线清理 `delSession` **异步**：调度协程发 `LobbyService.LeaveRoom` 与 `BattleService.LeaveBattle`，避免大规模断线打爆协程池。
  - 实现 `PushService`：`NotifyClient` / `NotifyClients`（批量）/ `NotifyAllOnline`（世界频道）。
  - 心跳：超过 `heartbeat_timeout`（45s）的空闲连接被关闭。

#### Login 登录（`server/login/`，HTTP 8200 + RPC 8201）

- 双暴露面：HTTP `HttpServer`（8200，servlet `/login` `/register`，JSON `{"name","password"}` → `{ok,token,account_id,msg}`）+ RPC `LoginService`（8201）。
- `LoginServiceImpl`：
  - **不直接碰 DB**，所有持久化走 `DataService` RPC。
  - 密码：`hashPassword = hex(sha1sum(password + salt))` + 32 字符随机盐（注释标注生产应换 OpenSSL EVP，README/proto 写"SHA256"但 sylar util 仅提供 sha1sum）。
  - `doRegister`：校验用户名（`[a-zA-Z0-9_]{2,16}`）→ 生成盐 + hash → `DataService.CreateAccount`。
  - `doLogin`：`GetAccountByName` → 比对 hash → 签发 48 字符随机 token → `DataService.SaveToken`（TTL 86400s）。
  - RPC：`ValidateToken`（返回 accountId+name，gate 首包校验）、`Register`、`Login`。

#### Lobby 大厅（`server/lobby/`，端口 8300）

- `lobby_main.cc`：`RpcChannelPool(etcd, 8)` 应对高频 lobby→gate 推送；注入两个 push 闭包（`NotifyClient` 调度到独立 IOManager 协程、`NotifyAllOnline` 用于世界频道），注释解释 RPC 调用栈（etcd+connect+send+recv+protobuf）太深，不能在 1MB 协程上同步执行。
- `LobbyServiceImpl`：
  - `LobbyRoom`（局前）：`roomId / name / mode("custom"|"match"|"pve") / started / Seat seats[8] / mapName("rainbow"|"ghost")`；`Seat` 带 `accountId/name/team/ready/gatewayId/gender/weaponId`。
  - 状态：`m_rooms`（roomId→LobbyRoom）、`m_nextRoomId{1000}`，`RWMutex` 保护。
  - RPC：`RoomList / CreateRoom / JoinRoom / LeaveRoom / Ready / SwitchTeam / SwitchWeapon / FriendAdd / FriendList / Chat / PrivateChat / ChatHistory`。
  - **`tryStart(roomId)` lobby→battle 交接**：≥2 座位、两队齐、全部就绪 → 加锁快照玩家 → 标记 `started=true` → **锁外** 调 `BattleService.EnterBattle`，失败回滚。这是"锁内快照 + 锁外 RPC"的标准范式。
  - `broadcastRoomUpdate` 推 `ROOM_UPDATE`；`broadcastRoomListToAll` 推 `ROOM_LIST_NOTIFY` 驱动大厅列表实时刷新。

#### Battle 战斗（`server/battle/`，端口 8400）

- `battle_main.cc`：共享 `TimeWheel`（100ms 步进，10min 上限）承载所有房间回合超时定时器（高频短定时器，O(1) 优于最小堆）；`RpcChannelPool(etcd, 8)`；注入 push（单发）与 bpush（批量，把 N 人房广播从 N 个 RPC/协程压成 1 个）。
- `BattleServiceImpl`：房间注册 `m_rooms`（roomId→BattleRoom）、`m_accountToRoom`，`RWMutex` 保护。每个 handler 在读锁里找到房间，再拿 **房间自己的 `m_roomMutex`** 直接调 `onXxx`——取代了早期 Actor/邮箱模型（曾把所有操作堆在一个协程栈上，叠加 RPC 推送链导致爆栈）。`LeaveBattle` 拆房时先 `onPlayerLeave`，再在服务锁里清账号索引，无账号时再拿房间锁 `markDestroying()`（取消回合定时器）后擦除，杜绝"孤儿定时器 → nextTurn → startTurnTimer"泄漏循环。
- `BattleRoom`（权威游戏状态，最大源文件）：锁为 `Mutex`（非 Spinlock），因为 `onShoot` 临界区要跑物理模拟（≈1500 步循环 + `removeCircle` 遍历数万格子），可能持锁数毫秒。
  - `BattlePlayer`：`accountId/name/team/gender/weaponId/x/y/hp/maxHp/angle/direction/gatewayId/alive`。
  - 常量：`FIRST_TURN_READY_MS = 12000`（首回合给客户端掉线/相机入场留宽限）、`SHOOT_RESULT_DELAY_MS = 2300`（给客户端播完弹道+爆炸再下一回合）。
  - `startGame()`：生成地形，红队围绕 `red_spawn_x`、蓝队围绕 `blue_spawn_x`（60 单位间距）放置，广播 `RoomReadyNotify`（含 `PhysicsParamsMsg`、完整玩家列表、**二维体素 `terrain_bitmap`**、map_name），再 `nextTurn()`。
  - `onShoot`：`PhysicsEngine::computeHitPoint2D` 求落点 → `calculateDamage` 算 AOE 伤害 → `m_terrain.removeCircle` 挖坑。
  - `broadcast` 优先用 `m_bpush`（批量），且把实际 RPC **重调度到新 IOManager 协程**，避免深 RPC 栈压在 `onShoot` 协程上。
  - `nextTurn` / `scheduleNextTurn`（`m_nextTurnPending` 重入保护）/ `checkGameOver` 驱动回合循环，发出 `GameOverNotify`；结算经 `DataService.SaveGameRecord`。

#### Data 数据（`server/data/`，端口 8500）

- `data_main.cc`：`DataServiceImpl::init(...)` 建 sylar MySQL `ConnectionPool`（含预热）+ 单个 hiredis `redisContext`（`m_redisMutex` 保护）。
- `DataServiceImpl : public DataService`：**唯一持久层**。所有方法在 RPC 协程内同步执行（ORM 连接池天然阻塞协程）。
  - MySQL：`sylar::Database` / `ConnectionPool`，`mysql_real_escape_string` 封装防注入。
  - Redis：`redisSet/Get/Del`，token 存为 `session:<token>` → accountId，带 TTL。
  - 18 个 RPC 方法，分组：账号（Create/Get*/Verify/UpdateGender）、资料（GetProfile/UpdateWinLoss）、Token（Save/Load/Delete）、记录（SaveGameRecord）、好友（Add/GetList）、聊天（SaveChat/GetChatHistory/GetPrivateHistory）。

### 5.3 共享物理与地形（`src/common/`）

#### 二维体素地形（`terrain2d.h/.cc`）

`Terrain2D`：2D 体素位图（`std::string m_bits`，行主序，1 bit = 1 世界单位，约 158KB/3000×420 房）。

- `generate(w,h,baseH)`：余弦起伏生成地形。
- `isSolid(x,y)` / `setSolid`：精确到格子的实体判定。
- `removeCircle(cx,cy,r)`：爆炸挖圆——**只清圆内格子，保留上方平台**（v0.4 的 1D 高度图做不到，这是切到 2D 的根本原因）。
- `columnHeight(x)`：从顶向下扫首个实体格。
- `bitmap()/setBitmap()`：序列化进 proto 传输。

#### 权威物理引擎（`ddt_physics.h/.cc`）

`PhysicsEngine`（静态类，服务端权威，客户端 C# `PhysicsSim.cs` 同公式重放）：

- `PhysicsParams`：`air_factor=0.89927083`、`wind_factor=5.8709153`、`gravity_factor=172.06527992`（Y 向上，正值=向下）、`force_factor=41.0`。
- 弹道：解析式空气阻力解，`em = 1 − E^(−af·t)`：

  ```
  cx = start_x + vx0·em/af + wind·wf·(t/af − em/af²)
  cy = start_y + vy0·em/af − g·(t/af − em/af²)        # g = 9.8·gravity_factor
  dt = 0.01, 最长飞行 15s
  ```

- `computeHitPoint2D`：轻量版，只返回落点（服务端用，避免把 1500 点轨迹压到协程栈）；`computeTrajectory2D`：完整轨迹（客户端复放）。
- `calculateDamage`：线性衰减 AOE。
- `getSlopeAngle2D`：由 ±3 列 `columnHeight` 差求坡度。
- `generateWind`：`(rand%201 − 100)/10.0`，约 [−10,+10]。

### 5.4 数据库 Schema（`src/server/schema.sql`）

数据库 `ddt_game`（utf8mb4），5 张表：

| 表 | 用途 | 关键列 |
|----|------|------|
| `accounts` | 账号凭证 | `id` PK、`name` UNIQUE(≤32)、`password_hash`(CHAR 64)、`salt`(CHAR 32)、`gender`(0/1/2)、`created_at` |
| `player_profiles` | 玩家资料 | `account_id` PK(FK CASCADE)、`nickname`、`level=1`、`exp=0`、`wins`、`losses` |
| `chat_history` | 聊天记录 | `id` PK、`channel`、`sender_id`、`sender_name`、`message`、`target_id`、`created_at`；索引 `idx_channel_time`、`idx_private` |
| `game_records` | 对战记录 | `id` PK、`player1_id`、`player2_id`、`winner_id`、`duration`、`created_at` |
| `friends` | 好友关系 | 复合 PK `(account_id, friend_id)`，双向 FK |

Redis（不在 schema.sql）：`session:<token>` → accountId，TTL 86400s。

## 7. RPC 框架

v1.0 在 sylar 基础上提供 **基于 Protobuf + etcd 的 RPC**，位于 `sylar/rpc/`（`etcd_client` / `rpc_provider` / `rpc_channel` / `rpc_channel_pool` / `rpc_controller` + `rpcheader.proto`）。**无任何 ZooKeeper 残留**，全部经 `etcd-cpp-apiv3`（gRPC 传输）。

### 7.1 架构

```
Caller (客户端)                              Callee (服务端)
    │                                            │
    │  RpcChannel.CallMethod()                   │  RpcProvider
    │  ├── EtcdClient.get(/Svc/Method) 查址       │  ├── EtcdRegistrar 注册(lease+keepalive)
    │  ├── 序列化 RpcHeader+args                  │  ├── notifyService 枚举方法
    │  ├── Socket 连接(池化可选)                   │  └── handleClient
    │  └── 发送/接收                               │      ├── 解析 RpcHeader
    │                                            │      ├── 查 method
    │  <──── TCP ────>                            │      └── CallMethod()
```

### 7.2 线路协议

```
请求: [4字节 header_size (网络序)][RpcHeader protobuf][args protobuf]
响应: [4字节 response_size (网络序)][response protobuf]
RpcHeader { service_name, method_name, args_size }
```

### 7.3 etcd 路径与保活

- 注册路径：`/{Service}/{Method}` → `advertise_host:port`。
- `EtcdRegistrar`（RAII）：注册时 grant lease（TTL 30s）+ 后台 keepalive + 自愈重注册（替代 ZK 临时节点的会话语义）。
- `EtcdWatcher`：前缀 watch，服务端推送变更（非轮询）。
- `etcd_client.h` 用 **PImpl** 隔离 etcd/protobuf/gRPC 头，保持框架其余部分 C++11 纯净（仅 `etcd_client.cc` 以 C++17 编译）。

### 7.4 连接池与发现缓存（`rpc_channel_pool`）

- `RpcChannelPool`：per-host socket 池（mutex+condvar，connect 在锁外执行以便让出协程）+ TTL 发现缓存。
- RAII `Guard` 自动归还 socket。
- **使用策略**：gate / login 用缓存短连接（连接池曾因 sylar hook 下 fd 复用竞态回滚）；lobby / battle 对 gate 高频推送，用 `RpcChannelPool(etcd, 8)`。

### 7.5 与服务端的契合

`rpc.proto` 声明 `cc_generic_services = true`，protoc 为每个 `service` 生成 `Stub`/`Service` 基类，sylar `RpcProvider` 直接在这些基类上分发。5 个微服务各 `notifyService` 注册自己实现的 Service，调用方经 `RpcChannel(etcd_endpoint)` 发现并调用。

### 8.6 LD_PRELOAD 垫片（`scripts/etcd_close_preload.cc`）

**生产级 workaround**：sylar 的 syscall hook 在静态构造期经 `dlsym` 解析真实 `close` 存到 BSS 全局 `close_f`；但 `libsylar.so` DT_NEEDED 依赖 `libetcd-cpp-api.so`，glibc 会先跑 gRPC 静态构造器，期间 gRPC 调 `close(fd)` 而 `close_f` 仍为 NULL → 空指针解引用 SIGSEGV（崩溃所有 sylar+etcd 程序）。

垫片 `close(fd)`：
- 运行时 `dlsym(RTLD_DEFAULT,"close_f")` 取 `close_f` **地址**（每次重新读 `*close_f_ptr`，不缓存）；
- 非空 → 经 `dlsym(RTLD_NEXT,"close")` 走 sylar hook（保留协程 fd 清理）；
- 为空 → 直接 `syscall(SYS_close, fd)`，绝不解引用空指针。

构建：`g++ -shared -fPIC -o lib/libetcd_close_fix.so scripts/etcd_close_preload.cc -ldl`
运行：`LD_PRELOAD=/abs/lib/libetcd_close_fix.so ./ddt_*`（`fleet.sh` 已自动应用）。

## 10. 实现细节

### 一、权威服务器 + 表现层客户端

对于竞技弹道游戏，防外挂与多端同步是重中之重。

- **服务端瞬间推演**：玩家按 FIRE → `BattleRoom::onShoot` → `PhysicsEngine::computeHitPoint2D`（带空气阻力/风力/重力的解析式，`dt=0.01`），求落点与 AOE 伤害。
- **客户端插值复放**：服务端把带时间戳的轨迹点经 `ShootResultNotify` 下发；客户端 `ProjectilePlayer` 不做物理运算，仅按游标在两点间插值。HP/命中/伤害一律用服务端字段。
- **评价**：杜绝客户端物理外挂，规避网络抖动导致的位置不同步。

### 二、二维体素地形（取代 1D 高度图）

- v0.4 用 1D 高度图，爆炸挖坑后"上方平台"无处安放，易穿地形/误判掉落。
- v1.0 改 `Terrain2D` 位图（1 bit=1 格），`removeCircle` 只清圆内格子，**保留圆内悬空平台**；`isSolid` 精确到格子。
- 服务端序列化为 `terrain_bitmap` 经 `RoomReadyNotify` 一次性下发；客户端 `TerrainRenderer` 重建为 `Texture2D`，破坏即改像素。

### 三、微服务化的并发范式（代码注释重点标注）

- **每会话发送队列 + 按需 drain 协程**（gate）：串行化同 fd 发送，规避 sylar 同 fd 并发 `addEvent(WRITE)` 触发的 `SYLAR_ASSERT` abort。
- **异步推送派发**（lobby / battle / gate 断线清理）：所有 `PushService` RPC 重调度到新 IOManager 协程——etcd+TCP+protobuf RPC 栈太深，压在游戏协程上会爆 1MB 栈。
- **批量广播 RPC**（`NotifyClients` / `BroadcastPushFn`）：N 人房广播从 N 协程压成 1。
- **锁内快照 + 锁外 RPC**（lobby `tryStart`）：锁内拷贝所需状态、释放、再跨服务 RPC，避免持锁跨 yield 点。
- **每房 Mutex**（battle，非 Spinlock）：物理临界区是毫秒级，Mutex 走 futex 睡眠而非烧 CPU。
- **短连接（gate/login）vs 连接池（lobby/battle）**：连接池在 gate 路径因 sylar hook 下 fd 复用竞态回滚，高频推送路径保留。
- **`markDestroying` + 定时器取消**（battle `LeaveBattle`）：防孤儿回合定时器在拆房后重新 `nextTurn → startTurnTimer` 的泄漏循环。

### 四、客户端架构：分层 + 跨场景状态

- `Session`（静态）承载跨场景状态（Token、缓存的首个 ROOM_READY/TURN_START 字节用于场景切换重放）。
- `GameFacade` 统一封装所有外发，避免业务层直接碰网络。
- `NetworkManager` 单例 + 主线程队列，保证 UI/逻辑只在主线程跑；收发后台线程化杜绝反压冻屏。
- 场景切换包缓冲（`StartTransition/EndTransition`）渡过 `LoadScene` 丢包窗口。

### 五、运维健壮性

- `LD_PRELOAD` 垫片解决 sylar hook × gRPC 静态构造的 `close()` 空指针崩溃。
- `fleet.sh` 一键管控 + 核心转储（`ulimit -c unlimited`）便于爆栈调试。
- 信号双段式：首次 SIGINT 优雅停 IOManager，再次强退。
